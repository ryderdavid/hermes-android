## Changed

- **`terminal` rows now state the command's purpose**, parsed from the shipped
  args. Examples: `pip install speedtest-cli` → "installing speedtest-cli";
  `which speedtest-cli fast 2>/dev/null` → "checking if speedtest-cli is
  installed"; `speedtest-cli --secure` → "running a speed test";
  `sudo apt-get install -y curl && which curl` → "installing curl, checking if
  curl is installed"; `grep -rn "X" lib/` → 'searching lib/ for "X"';
  `gh release create …` → "publishing a release"; `bd close …` → "closing an
  issue". Compound commands (`&&`, `;`, `|`) are split and each step is
  summarized; redirects, `sudo`, and `env` prefixes are stripped first.
  Known tools map to their purpose (speedtest, pytest, nmap, docker, ffmpeg,
  …); unknown binaries at least get named — "running `mytool`" — instead of
  the generic "running a shell command". The raw command remains in the row's
  detail line.
- Same mapping applies to the REST streaming path's redacted `label` previews.
